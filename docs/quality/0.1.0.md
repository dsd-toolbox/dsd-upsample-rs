## Run

- Host: AMD Ryzen 9 3950X, 32 threads, Fedora 44, shared with other niced work; `nice -n 10`, memory capped at 95 GiB.
- Command: `tools/quality-compare.sh`, split into two shares run at once (every DSD256 device with `--jobs 1`; the PCM to DSD64 and DSD128 devices with `--jobs 2`), then a `--merge` run that wrote the tables. Exit status 0 for all three.
- Wall time: 2 h 0 min (2026-11-25). Largest process peak: 36.08 GB (33.6 GiB), PCM to DSD256 from 44.1 kHz.
- Builds: Rust 1.100.0, `cargo build --locked --release -p dsd-upsample-cli`, from clean trees of the 0.1.0 code and of the previous candidate, 0.1.0-rc1 (not published). The SHA-256 values in the first table are of those builds; the released 0.1.0 binary is a separate build of the same code.
- dsd-measure 0.1.2 (commit 3eaec2d, as the suite pins), in a fresh virtual environment.

## Conclusion

At equal explicit settings 0.1.0 is identical to 0.1.0-rc1 on all 8 conversions (no change beyond 0.1 dB and identical nulls), and at each build's defaults every change beyond repeatability lies inside the suite's `[[quality.explained]]` entries (recorded as version 0.1.0-rc2: the −6 dB default gain, see [design decisions](../design.md#decisions)).
