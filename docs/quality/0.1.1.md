# Quality: 0.1.1 against 0.1.0

0.1.1 converts every input to the same bytes as 0.1.0, so the measurements of
[0.1.0](0.1.0.md) hold for it unchanged; the dsd-measure comparison was not run again.

## Why the output cannot have changed

0.1.1 changes no arithmetic of the conversion. Its changes to the converter's code are: the
conversion joins its front-end threads, and batch mode its worker threads, before returning
(after the last output byte is written); a damaged-header check reports a format error instead
of an I/O error; and the run-time engine id (`engine_id()`). The golden hashes (the tests in
`crates/dsd-upsample/tests/pipeline.rs`) are the same file as in 0.1.0 and pass.

## Byte identity, measured

`tools/quality/identity.sh` converts the same inputs with both command-line builds and compares
the outputs byte for byte. The inputs are made by the 0.1.0 build's own `gen`: DSF and DFF at
DSD64, DSD128 and DSD256, and WAV at 44.1, 48, 88.2, 96, 176.4, 192, 352.8 and 384 kHz in 16,
24, 32-bit, f32 and f64 samples; mono, stereo and 6 channels; quiet, −6 dB and tones above full
scale.

| Cases | What | Same |
|---|---|---|
| 105 | Single files: every output rate (DSD64, DSD128, DSD256, PCM at 88.2, 176.4 and 352.8 kHz), the pipelined and the `--single-thread` path, orders 5 to 8, `--dither`, `--gain`, `--limit`, `--cutoff`, DFF output, `--tag` | 105 |
| 2 | Batch mode, 10 files to DSD256, with `--jobs 1` and `--jobs 4` (the code whose threads 0.1.1 joins) | 2 (20 files) |
| 4 | Refusals (order 8 at DSD128, DSD64 output from DSD input, PCM output from DSD128): exit status and message | 4 |

All 111 cases are the same. The check can fail: with the candidate's gain moved by 0.01 dB
(`--gain -5.99` in place of the default −6), all 107 cases that write a file differ.

## Run

- Host: AMD Ryzen AI 9 HX 370, Fedora 45, `nice -n 10`.
- Builds: Rust 1.100.0, `cargo build --locked --release -p dsd-upsample-cli`, from clean trees of
  v0.1.0 and of the 0.1.1 candidate. SHA-256 of the builds: 0.1.0
  `e53755564965f41ecce83a4e8ee8dbc8355e1f01e2d9de37aefada0e52a15c88`, 0.1.1 candidate
  `2a349c230354466d7faa39f6ac51c7204d9ed3cf6cbb3f53715488ee58e2dab5` (they differ in the version
  string and the changed code above).
- Command: `tools/quality/identity.sh OLD NEW WORKDIR`, exit status 0; wall time about 2 min
  (2026-11-25).

## Conclusion

0.1.1 is byte-identical to 0.1.0 on every case measured, golden hashes included; every figure on
the [0.1.0 page](0.1.0.md) applies to 0.1.1.
