# Resampler design

How 48 kHz-family PCM (48, 96, 192 and 384 kHz) reaches the converter's 44.1 kHz-family
chain, and the measurements that show the rate change costs nothing measurable. Designed and
measured 2026-11-24.

## Specification

- Synchronous, rational: 44100/48000 = 147/160 exactly, so output sample `m` sits at input
  time `m × 160/147`; no asynchronous rate estimation, no drift.
- Passband at least 0 to 20 kHz at 48 kHz input (0 to 20/44.1 of the new rate in general,
  0.907 × its Nyquist frequency), flat, ripple stated.
- Transition below the new rate's Nyquist frequency: stopband from 22.05 kHz at 48 kHz
  input, so whatever aliases is attenuated by the full stopband.
- Error far below the modulator's in-band floor at every output rate. The defaults reach
  121.1, 160.0 and 198.4 dB SINAD at DSD64, DSD128 and DSD256 (1 kHz at 0 dB SACD from a
  44.1 kHz f64 source, [below](#measurements)), so the resampler's own in-band error must
  sit near −210 dB or lower.
- Linear phase; delay compensated exactly, so output length and alignment follow the rules
  of the rest of the chain.
- Deterministic: the same bytes on every platform, build profile and thread setting.

## Where the resampler sits

Each 48 kHz-family rate is mapped to the 44.1 kHz-family rate below it (48 → 44.1,
96 → 88.2, 192 → 176.4, 384 → 352.8 kHz); the result then takes exactly the chain of that
rate (steep ×2 stage, half-bands, modulator). One prototype filter serves all four rates,
because its band edges are fractions of the rate.

The alternative was to resample straight to twice the partner rate (48 → 88.2 kHz, ratio
147/80) and skip the steep ×2 stage that follows. With the same band edges (anything else
would let 22.05 to 24 kHz content through, where the next half-band stage cannot reject its
images) it needs the same prototype, so the quality is the same; it computes twice as many
resampler outputs and saves the steep stage. Measured cost per second of 48 kHz input (see
[Speed](#speed)): 3.6 ms to the partner rate plus 1.4 ms for the steep ×2
stage (5.0 ms per channel-second) against 7.2 ms straight to 88.2 kHz. The partner mapping is faster and keeps the 48 kHz-family
output on the very chain the 44.1 kHz family uses, which is what makes the measurements
below a clean comparison, so it was chosen.

## Filter

Generated by `tools/gen_resampler.py` (NumPy, f64), committed as
`crates/dsd-upsample/src/resample_table.rs`.

| Property | Value |
|---|---|
| Method | Kaiser window (J. F. Kaiser 1974), β from Kaiser's formula for 250 dB (26.5913) |
| Prototype rate | 147 × input rate (7.056 MHz at 48 kHz input) |
| Length | 58,241 taps (centre 29,120, a multiple of 160); 397 taps per polyphase branch |
| Passband | 0 to 20/44.1 × output rate, 0.907 × its Nyquist (20 kHz at 44.1 kHz output; 40, 80, 160 kHz at the higher rates) |
| Passband ripple | −4.7e-12 to +3.6e-12 dB (measured, 2^24-point FFT) |
| Stopband | −244.6 dB at the output Nyquist frequency (22.05 kHz at 44.1 kHz output; 1 Hz grid up to 24 kHz), −256.5 dB from the input's Nyquist (24 kHz) up (measured) |
| Phase | linear (symmetric taps) |
| Delay | 182 samples at the output rate (4.13 ms at 44.1 kHz) |
| Gain | 147 (the upsampling factor): DC passes at unity |

The script checks the measured ripple (within ±1e-10 dB) and stopband (−240 dB or lower)
on every run and fails if the design misses them.

Simulated through the prototype alone (SciPy `upfirdn`, 48 kHz in, 44.1 kHz out, full-scale
tone, error against the exact tone after the delay, 20 Hz to 20 kHz, 1 s):

| Tone | In-band error re the tone | Peak error |
|---|---|---|
| 1 kHz | −271.2 dB | −267.3 dBFS |
| 10 kHz | −267.4 dB | −264.0 dBFS |
| 19 kHz | −260.2 dB | −257.0 dBFS |
| 19.99 kHz | −248.8 dB | −247.5 dBFS |

So the resampler's error is at least 49 dB below the DSD256 floor; tones near 20 kHz meet
the stopband sidelobes (their images land 2 to 8 kHz past the stopband edge) and stay
below −248 dB.

Why this length: the stopband peak sits at the stopband edge, on the skirt of the main lobe,
and its level depends on where the response's first null falls relative to the edge, so it
swings by about 10 dB between neighbouring designs instead of following the formula. Edge
peaks measured for the formula's attenuation (`gen_resampler.py`'s response with ATTEN_DB
changed): 240 dB → −226.0, 244 → −229.4, 246 → −241.3, 248 → −232.9, 250 → −244.6,
252 → −236.3, 254 → −247.9 dB. 250 dB is the choice: it clears the −240 dB acceptance limit
by 4.6 dB (246 dB would clear it by 1.3 dB, at 1.7 % fewer taps). f64 arithmetic is far below
this: in an exploratory comparison not included in this repository, the difference between
the table and the same design computed in 80-bit long double had a response peak of
−307 dB, so rounding does not limit the design.

## Implementation

`Resampler` in `crates/dsd-upsample/src/filters.rs`:

- The 147 branches are built from the stored half by copying taps, without arithmetic.
- Output `m` is `Σ_j phase[p][j] · x[n − j]`, `n = ⌊160m/147⌋`, `p = 160m mod 147`, each sum
  in ascending `j` in f64 without fused multiply-add. Four outputs are computed side by side
  (independent sums, the order within each unchanged).
- Streaming: zero history before the input, a phase counter, a history of 396 samples kept
  between pushes; the split of the input into pushes never changes an output bit.
- Delay: the centre tap is a multiple of 160, so the delay is a whole 182 samples at the
  partner rate; it is scaled to the output rate and added to the other stages' delays, and
  the bit packer drops that many leading samples as for every input. The output has exactly
  `input samples × output rate / input rate` samples (rounded down).
- The gain is applied after the resampler, at the partner rate.
- A non-finite or out-of-range input sample (NaN, ±infinity, or a value so large that
  the filtered result overflows) reaches every output whose 397-tap window covers it, 8.3 ms
  of input at 48 kHz, and then the following stages' spans. The modulator limits those
  samples (NaN to 0) and keeps running, as for 44.1 kHz input, but the limited stretch is
  longer: 13.15 ms per such sample at 48 kHz against 4.90 ms at 44.1 kHz (DSD128, measured
  by `tests/stream.rs` `non_finite_pcm_is_limited_not_stuck`).
- The output length `input samples × output rate / input rate` (rounded down) need not be
  a multiple of 8 for 48 kHz-family input (48,001 frames at 48 kHz give 5,644,917 DSD128
  samples): the last byte then holds the remaining samples and idle-pattern padding, as
  for DSD input of odd length. 44.1 kHz-family PCM always gives whole bytes.

## Tests

- `filters::resampler_tests::matches_python_reference`: 2,048 outputs bit-identical to the
  generator's reference loop (same taps, same summation order), which itself agrees with
  SciPy's `upfirdn` to 2.4e-15.
- `chunking_does_not_matter`, `length_dc_and_delay`: push sizes from 1 sample up; output
  count; DC gain within 1e-12; the delay.
- `convert::alignment::pcm_inputs_align_with_the_output`: for every PCM input rate (both
  families) to DSD64, DSD128 and DSD256, the modulator input after the delay compensation
  equals the ideal sine at the output rate within 1e-6 (one output sample of misalignment
  would be 5e-4 at DSD128).
- Golden SHA-256 hashes of a 48 kHz and a 96 kHz input to DSD128 (`tests/pipeline.rs`),
  single-threaded equal to threaded; streamed equal to whole-file at 48 and 192 kHz
  (`tests/stream.rs`); the stability test (`tests/stability.rs`) adds the full legal and hot
  signal set at 48 kHz and the band-edge set at 96 and 384 kHz; the soak test converts 96
  and 48 kHz WAV input; the fuzz targets accept every new rate; the C smoke test streams
  48 kHz, accepts 96, 192 and 384 kHz and refuses 32, 64 and 768 kHz.
- Odd lengths (48,001 frames at 48 kHz, 96,007 at 96 kHz, 4,001 at 192 kHz): exact output
  length and a partial last byte with idle padding, whole-file (`tests/pipeline.rs`) and
  streamed in any split (`tests/stream.rs`). Non-finite samples at 48 kHz are limited and
  the modulator keeps running (`tests/stream.rs`).

## Measurements

Full tables: [measurements, 48 kHz-family input](measurements.md#48-khz-family-input).
Each signal is converted from a 48 kHz-family source and from its 44.1 kHz-family partner;
mono f64 WAV, CLI defaults with `--gain 6.0206`, reference decoder, levels in dB re 0 dB
SACD.

| Comparison (48/96/192/384 kHz source against 44.1/88.2/176.4/352.8 kHz) | DSD64 | DSD128 | DSD256 |
|---|---|---|---|
| SINAD, 1 kHz at 0 dB SACD, 48 kHz source (dB) | 121.0 | 159.9 | 198.4 |
| SINAD, 1 kHz at 0 dB SACD, 44.1 kHz source (dB) | 121.1 | 160.0 | 198.4 |
| SINAD, 1 kHz at 0 dB SACD, 384 kHz source (dB) | 121.3 | 160.1 | 198.6 |
| SINAD, 1 kHz at 0 dB SACD, 352.8 kHz source (dB) | 121.1 | 160.1 | 198.5 |
| Largest SINAD difference, all four pairs, 0 and −3 dB SACD (dB) | 0.4 | 0.3 | 0.3 |
| Largest CCIF or SMPTE IMD difference, all four pairs (dB) | 0.8 | 1.1 | 0.6 |

For scale: the four 44.1 kHz-family rates differ from each other by up to 0.5 dB in SINAD
and 1.8 dB in IMD, so the differences above are the measurement's scatter.

- Flatness (32-tone multitone to DSD128): −2.6e-6 to +1.8e-6 dB from 28 Hz to 17 kHz,
  reference decoder included; the families differ by at most 3.3e-8 dB. A 19.99 kHz tone
  comes out within 3.0e-6 dB of its input level from 48, 96 and 192 kHz.
- Band edges (DSD256): tones at 0 dB SACD in the stopband (22.1 to 24 kHz at 48 kHz
  input, 44.2 to 48 kHz at 96 kHz, 88.3 to 96 kHz at 192 kHz) read at the output's own noise
  at their frequency. Their alias frequencies (the new rate minus the tone: 20.1 to 22 kHz
  at 48 kHz input, always above the audio band) read at the output's noise there too, for
  example −224.7 dB SACD at 21.1 kHz for a 23 kHz tone against −222.4 dB with silence in.
  No alias is visible above the noise of a DSD256 output; the filter's −244.6 dB is below
  what the measurement can show. The in-band residual of these tones (−206.9 to
  −207.7 dB SACD) equals that of negligible non-zero inputs (−206.6 to −207.5 dB SACD).
- Real music: the 32 48 kHz-family files of the release test set (48, 96 and 192 kHz; mono,
  stereo and 6-channel; FLAC and WAV; 8.1 channel-hours) converted to DSD128 and DSD256: 0
  limited samples, 0 clipped states, 0 resets in all 31 readable files. The 32nd, a mono 96
  kHz FLAC, is truncated (its header declares 3,255 more frames than it holds, which `flac
  -t` confirms) and is refused with `invalid file: FLAC stream ended after 25964544 of
  25967799 frames`. *Measured at order 6, limit 0.51 and gain −3 dB, on an
  earlier build of 0.1.0 (not the release defaults, which use gain −6 dB).*
- A measurement pitfall found on the way: sines generated as `sin(2π f n / fs)` in f64
  carry in-band spurs near −220 dB SACD after a few seconds at high `f` (the rounding of
  the growing argument); a 23 kHz tone generated that way leaves them in the audio band
  after any filter. The band-edge tones therefore use exact phase (the argument reduced in
  integers), see `tools/measure_resample.py`.

## Speed

AMD Ryzen AI Max+ 395, release build, 4 CPUs, no other timing run on the machine.

Resampler alone, per channel-second of input (`stage_timings`, one thread):

| Input | Output | Time | Taps per output |
|---|---|---|---|
| 48 kHz | 44.1 kHz | 3.6 ms | 397 |
| 48 kHz | 88.2 kHz (the rejected alternative) | 7.2 ms | 397 |
| 384 kHz | 352.8 kHz | 29.2 ms | 397 |
| (for scale) steep ×2 stage, 44.1 to 88.2 kHz | | 1.4 ms | |
| (for scale) modulator at DSD256 | | 89 ms | |

The cost grows with the input rate (about 0.08 ms per kHz of input per channel-second).

Whole conversions, 60 s stereo f64 WAV, 1 kHz at −6 dB, best of 3:

| Source | DSD128, threads (default) | DSD128, `--single-thread` | DSD256, threads (default) | DSD256, `--single-thread` |
|---|---|---|---|---|
| 44.1 kHz | 2.55 s | 6.28 s | 5.11 s | 12.46 s |
| 48 kHz | 2.57 s (+0.8 %) | 6.74 s (+7.4 %) | 5.13 s (+0.3 %) | 12.95 s (+3.9 %) |
| 176.4 kHz | 2.57 s | 6.69 s | 5.11 s | 12.84 s |
| 192 kHz | 2.59 s (+0.6 %) | 8.44 s (+26 %) | 5.12 s (+0.1 %) | 14.57 s (+13 %) |

With the default threads the front end (resampler included) runs beside the modulator,
which sets the pace, so 48 kHz-family input converts as fast as its partner rate; on a
single thread the resampler's work adds up, most at 192 kHz.

## Reproducing

```sh
python tools/gen_resampler.py --check            # table and reference vector up to date
python tools/gen_resampler.py --check --report   # also the tone simulation above
cargo test --release -p dsd-upsample resampler
cargo test --release -p dsd-upsample --test pipeline golden_48k_family
cargo build --release -p dsd-upsample-cli
python tools/measure_resample.py --bin target/release/dsd-upsample --work /tmp/resample-meas
cargo test --release --lib stage_timings -- --ignored --nocapture
```

`tools/gen_resampler.py` needs the pinned tool environment (`tools/requirements.txt`);
`tools/measure_resample.py` needs NumPy and SciPy.

Part of the [DSD Toolbox](https://github.com/dsd-toolbox/dsd-toolbox).
